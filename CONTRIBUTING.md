# Contributing to Moon Technologies projects

Thank you for helping! This guide applies to every repository in the organization unless a project has
its own `CONTRIBUTING.md`.

## Before you start

- **Bugs:** open an issue with steps to reproduce, what you expected and what happened, plus your OS and version.
- **Ideas:** open an issue first so we can agree on the approach before you write code.
- **Security problems:** do **not** open a public issue — see [SECURITY.md](SECURITY.md).

## Making a change

1. Fork the repository and create a branch from `main` (`feat/short-description` or `fix/short-description`).
2. Keep changes focused: one topic per pull request.
3. Add or update tests. CI must pass.
4. Update the documentation when behaviour changes. Docs are written in English; Spanish translations are welcome.
5. Use clear commit messages in the imperative mood: `Add camera switching`, `Fix reconnect after Wi-Fi drop`.
6. Open the pull request and describe *what* changed and *why*.

## Style

Follow the conventions of the code around you. We value clean architecture, small functions with clear names,
and comments that explain *why*, not *what*.

## Licensing

By contributing you agree that your contribution is licensed under the license of the repository you contribute
to (usually Apache-2.0; fonts use the SIL Open Font License 1.1).
